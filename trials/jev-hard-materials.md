- 10 functions × (correct + buggy_a + buggy_b + tests). (a) items mirror

- Correct implementations run 19–34 lines (see the note on levenshtein
  below) — multi-step, versus the original set's ~5–10 line functions.

## Method (same as the original, report §9.1)

Hand-authored correct implementations + tests from precise specs.
Buggy variants generated by magicoder (:8202 direct, temp 0) under
EXACT mutation instructions, one mechanical edit each; the parser keeps
the first fenced block defining the function that differs substantively
from correct (3 attempts). **The test gate is binding:** the same
tests must PASS on correct and FAIL on each buggy variant (assertion
failure or test error both count as failing; a harness crash does not
count). Validity is gated by verification, not by mutation fidelity —
one hand-applied fix is documented below.

## How "harder" was built (three axes)

1. **Subtler bugs** — off-by-one in edge cases only (stale deque index,
   last-window drop, leftover-unit shortfall, 255 boundary), wrong
   operator precedence in a nested expression (EMA update, quantile
   interpolation), swapped same-type values (minute/second multipliers,
   first/last fill, tie-break sign), and single-index slips (DP cells,
   shifted character compare).
2. **Larger functions** — 19–34 lines, multi-step (deque state, DP
   table, cumulative-weight scan, apportionment loop, CIDR parser).
3. **Ambiguous specs, (b) only** — four functions carry an ambiguity
   that matters for pick-better. Wiring (strict): (a) items use the
   PRECISE `spec` (the resolving clause stated); (b) items use `spec_b`
   (the clause removed, an "Ambiguity note" flagging the gap, the
   reading unstated). The decider must infer the standard reading.
   **RUN-JOB WARNING: the test-encoded readings below are ground-truth
   bookkeeping for scoring — they must NOT be put into item prompts.**

### Ambiguous functions and their test-encoded readings (NOT in prompts)

- **merge_sorted_lists** — ambiguity: order of equal-key elements from
  different lists. Tests encode: a-before-b (stable). Rival variant:
  buggy_a (`<` instead of `<=`, takes from b on ties).
- **allocate_budget** — ambiguity: how remainder ties break. Tests
  encode: larger amount first, then earlier index. Rival variant:
  buggy_b (tie-break sign flipped, smaller amount first).
- **validate_ipv4_cidr** — ambiguity: whether leading zeros in octets
  (e.g. '010') are allowed. Tests encode: rejected (except '0').
  Rival variant: buggy_b (leading-zero check deleted).
- **moving_median** — ambiguity: how an even-window median is defined.
  Tests encode: mean of the two middles. Rival variant: buggy_b
  (lower middle instead of the mean).

## Per-function entries

Format per function: spec (short) · correct lines · buggy_a mutation +
gate · buggy_b mutation + gate · source.

### 1. exponential_moving_average (24 lines)

EMA with seed/initial rules. Correct 7/7. buggy_a: seed double-count
(`rest = values` instead of `values[1:]`) — FAIL 3 tests. buggy_b:
precedence (`alpha*x + 1 - alpha*ema` instead of
`alpha*x + (1-alpha)*ema`) — FAIL 3 tests. Both magicoder.

### 2. merge_sorted_lists (24 lines) — AMBIGUOUS (b) only

Stable merge with optional key. Correct 9/9. buggy_a: stability flip
(`<` instead of `<=`, rival reading) — FAIL 1 test (the tie test
only). buggy_b: leftover drop (`a[i+1:]` / `b[j+1:]`) — FAIL 6 tests.
Both magicoder.

### 3. parse_duration (25 lines)

Duration strings to seconds (d/h/m/s, case-insensitive, bare number =
seconds). Correct 12/12. buggy_a: multipliers swapped (m→1, s→60) —
FAIL 5 tests. buggy_b: bare number read as minutes (`int(t)*60`) —
FAIL 1 test (the bare-number test only). Both magicoder.

### 4. weighted_quantile (34 lines)

Weighted quantile, cumulative-weight scan + linear interpolation.
Correct 12/12. buggy_a: denominator slip (divide by `cumulative`
instead of the segment weight) — FAIL 3 tests. buggy_b: precedence
(`prev + frac*value - prev` instead of `prev + frac*(value-prev)`)
— FAIL 3 tests. buggy_b HAND-APPLIED (see Notes).

### 5. sliding_window_max (22 lines)

Deque-based sliding maximum. Correct 10/10. buggy_a: expiry
off-by-one (`<` instead of `<= i - window`, stale max kept one step
too long) — FAIL 3 tests. buggy_b: output-condition off-by-one
(`i >= window` instead of `i >= window - 1`, first window dropped)
— FAIL 6 tests. Both magicoder.

### 6. levenshtein (19 lines)

DP edit distance with row swap. Correct 10/10. buggy_a: shifted
compare (`b[j-2]` instead of `cb`) — FAIL 5 tests. buggy_b: diagonal
slip (`prev[j]` instead of `prev[j-1]`) — FAIL 6 tests. Both
magicoder. Note: 19 lines, one under the 20-line guideline — kept
as-is rather than padding, because any added line would appear as
noise in every variant diff (variants were generated from this
correct file); it is a multi-step DP function either way.

### 7. interpolate_missing (21 lines)

None-gap filling by linear interpolation + edge fill. Correct 8/8.
buggy_a: denominator off-by-one (`right-left+1`) — FAIL 3 tests.
buggy_b: trailing fill swapped (`points[first]` instead of
`points[last]`) — FAIL 1 test (the trailing-edge test only). Both
magicoder.

### 8. allocate_budget (22 lines) — AMBIGUOUS (b) only

Largest-remainder apportionment. Correct 11/11. buggy_a: leftover
off-by-one (`range(leftover-1)`) — FAIL 3 tests. buggy_b: tie-break
sign flipped (smaller amount first, rival reading) — FAIL 1 test
(the tie test only). Both magicoder.

### 9. validate_ipv4_cidr (27 lines) — AMBIGUOUS (b) only

CIDR validation returning (address, prefix). Correct 12/12.
buggy_a: 255 boundary (`>= 255` instead of `> 255`) — FAIL via 1
test ERROR (test_max raises ValueError on valid input; the gate
counts test errors as failures, and the error IS the bug). buggy_b:
leading-zero check deleted (rival reading) — FAIL 1 test. Both
magicoder.

### 10. moving_median (20 lines) — AMBIGUOUS (b) only

Sliding-window median. Correct 9/9. buggy_a: loop-bound off-by-one
(`range(len-window)` drops the last window) — FAIL 5 tests.
buggy_b: lower middle instead of mean of middles (rival reading) —
FAIL 2 tests. Both magicoder (see Notes for the float-wrapper
adaptation).

## Notes and deviations (all owned plainly)

1. **Pre-generation test fix (author's own test, not a variant).**
   The EMA `test_initial` first compared a whole list with
   `pytest.approx([...])`; the verify shim's approx handles scalars
   only (list minus list raises inside `__eq__`, caught as False),
   so the test failed on the CORRECT implementation. Fixed element-wise
   (`all(got == approx(want) ...)`); correct then passed 7/7. The shim
   is unchanged; no other test used list-approx.
2. **One hand-applied variant (weighted_quantile buggy_b).**
   Magicoder's output was `prev_value + frac * value` — parens dropped
   AND the trailing `- prev_value` dropped. The specified mutation is
   `prev_value + frac * value - prev_value` (parens dropped only).
   Hand-applied the specified form (`jev-hard-fix-weighted.py`) and
   re-ran the gate: buggy_b now fails 3 tests (was 4 with the looser
   form). AB_VALID holds either way; the specified form is what
   ships.
3. **One accepted adaptation (moving_median buggy_b).** Specified:
   `float(frame[mid-1])`; shipped: `frame[mid-1]` (the float wrapper
   dropped, the semantic change — lower middle instead of mean — is
   exactly as specified). No test outcome differs between the two
   forms (int vs float equality only matters where the values are
   already equal, and there the mean equals the lower middle anyway).
   Accepted, not counted as a miss.
4. **Cosmetic comments from magicoder** on three variants
   (allocate_budget buggy_a, weighted_quantile buggy_a,
   validate_ipv4_cidr buggy_a: "# Changed ..." remarks) plus trailing
   blank lines on several variants. Harmless: the decider sees the
   diff regardless, so the comments reveal nothing the diff does not.
5. **validate_ipv4_cidr buggy_a fails via error, not assertion**
   (test_max raises ValueError on the valid 255 input). The gate
   counts test errors as failures, and the error is the bug itself
   (rejecting valid input) — not a harness crash (harness_ok True).
6. **No hint leaks of the original report's kind.** No variant
   comment names a verdict; the (b) ambiguity notes flag the gap
   without resolving it; the test-encoded readings live in this
   manifest only, never in item prompts.
7. **Original materials untouched.** Everything new lives under
   `materials-hard/` and `jev-*-hard.*`; no file in `materials/` or
   the original `jev-*.json`/`jev-*.py` was modified.
